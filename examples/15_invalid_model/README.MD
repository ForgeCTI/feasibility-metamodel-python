# Invalid Model

## Purpose

Demonstrate how the validation system detects reference and type errors in a model containing intentionally corrupted relationships.

This example also illustrates the distinction between preventive checks performed by the core components and the validation process executed through `Model.validate()`.

## Scenario

The scenario contains four entities and two relationships.

**Entities:**
- 1 `Organization`
- 1 `Sector`
- 1 `ThreatActor`
- 1 `Expertise`

**Relationships:**
- 1 `operatesIn` with an invalid reference
- 1 `hasExpertise` with an invalid target type

Both relationships are intentionally modified to introduce structural inconsistencies.

## Validation

### 1. Reference validation

The `operatesIn` relationship connects an `Organization` to a `Sector` that has not been added to the model.

Under normal circumstances, `Model.add()` would reject this relationship because one of its endpoints does not belong to the model.

To demonstrate the Reference Validator, the relationship is inserted directly into the internal collection:

```python
model._relationships.append(invalid_reference)
```

This intentionally bypasses the preventive checks performed by `Model.add()`.

The Reference Validator subsequently detects that the target entity is not present in the model.

### 2. Type validation

The `hasExpertise` relationship is initially created with valid endpoints: a `ThreatActor` and an `Expertise`.

After the relationship has been successfully added, its target is deliberately replaced with a `Sector`:

```python
invalid_type._target_entity = sector
```

Although `Sector` belongs to the model, it is not a valid target type for `hasExpertise`.

This modification bypasses the type checks performed during relationship construction, allowing the Type Validator to detect the inconsistency.

### 3. Validation order

The complete validation process is executed through `Model.validate()`.

Reference and type validation are performed first.

Because structural errors are detected, the Cardinality Validator is not executed. This prevents potentially misleading cardinality errors caused by structurally inconsistent relationships.

**Expected result:**

```text
Entities: 4
Relationships: 2
Valid: False
Errors: 2
Warnings: 0
```

The report contains:
- One error generated by `referenceValidator`.
- One error generated by `typeValidator`.

No cardinality errors or warnings are produced.

## Run

From the repository root:

```bash
python examples/15_invalid_model/main.py
```

## Notes

**Direct manipulation of internal attributes is used exclusively for demonstration purposes.**

The instructions involving `_relationships` and `_target_entity` are not part of the recommended public API.

They are necessary in this example because the normal model construction mechanisms already prevent the invalid relationships from being created or added.

This demonstrates three complementary levels of protection:

1. **Relationship construction:** checks endpoint compatibility.
2. **Model insertion:** checks endpoint membership.
3. **Model validation:** detects structural inconsistencies in the resulting model, including intentionally corrupted internal states.

In normal application code, relationships should be created and inserted using the public interfaces rather than modifying internal attributes directly.

This example is intended to illustrate validation behavior, not to represent a complete cyber-attack feasibility analysis.
